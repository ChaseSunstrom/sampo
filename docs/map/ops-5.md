- Unaccounted clauses (T-2138): when the final message claims done and `sampo clauses` left parts of the last request mapped to no task (meta `clauses.open`, set within the last day), the Stop hook holds the stop once per clause (a clause already named never holds it again; an undated list counts as stale), naming up to five of them: capture each, answer it, or `sampo clauses --note N "<why>"`. - Test claims (T-0886): when the final message says the tests, suite, checks or gates pass (or are green), the Stop hook reads the turn's tool calls from the transcript (`fmhooks._turn_calls`: since the user's last prompt, the last 4 MB) and holds the stop once per message when a file tool edited a file after the last test run (or none ran after edits), or that run failed (is_error, or a failure in its last 300 characters; `sampo task prove`'s intended red line aside). Test runs are Bash commands naming a runner (pytest, run.py, npm test, go test, cargo test, make test, sampo check, sampo task evidence/finish/prove --run…). - Ablation at close (T-1067): `sampo task finish ID --ablate` runs the hunk proof on the linked tests (sampo check's affected template) after the close's own checks, prints "N/M hunks proven" naming each hunk no test notices, and never fails or blocks the close (any error prints "ablation skipped: why"). - Hunk mutation proof (T-0271, pass 2): `sampo task prove ID --hunks --run CMD [--max 20]` diffs the task's code files (not tests or docs) from its start snapshot at -U0, makes a detached worktree of the current tree (a commit-tree of it), and for each hunk reverts it alone (by its position in the new file, T-0286; new Python files per top-level definition) — in a checkout shipping Sampo's hook (its committed-library fallback), HEAD is set to the task's base while checks run, so a mutation that crashes the hook falls back to pre-change code and fails instead of passing on the unmutated tree (T-0297), runs CMD there, and restores the file; every mutated and restored version gets its own whole-second mtime so mtime+size caches (.pyc, make) can't reuse the other version. The check must pass on the unchanged scratch tree first (ignored files like .venv aren't copied, and a check that fails anyway would "prove" every hunk); after each hunk the scratch tree is reset and cleaned (a deleted file that -R recreated goes again); a timeout counts as not tested. A hunk whose removal still passes is unproven. Only a complete run (every hunk tested and proven, none cut by --max) is passing evidence (`N/N hunks proven`); anything else is an inconclusive line naming what's unproven or untested (never counts as passing); exit 1. The working tree is never touched.
